Egress control for agent containers

Decide what your containers can reach.
Then prove it.

Outcall is a host-level firewall daemon for Docker agent containers. It creates an isolated bridge, applies nftables policies, filters DNS, proxies HTTP, and gives operators a single source of truth for what containers may talk to.

How it works

One daemon on the host. One bridge. One source of truth for policy.

   Operator                                Agent Container
      │                                          │
      │ outcall CLI                              │ outcall-agent (shim)
      │ via host.sock                            │ via agent.sock
      ▼                                          ▼
  ┌─────────────────────  outcalld  ─────────────────────┐
  │  rules engine  •  bridge  •  nftables                │
  │  DNS filter    •  HTTP proxy   •  network manager    │
  └──────────────────────────┬───────────────────────────┘
                             │
                       outcall0 bridge
                             │
                       Internet (filtered)
  • Bridge + nftables
    Isolated L2 segment. Default-deny. Allow rules in YAML.
  • DNS filter
    Resolves only what the rule set permits. Blocks the rest at name lookup.
  • HTTP proxy
    Inspects HTTP/HTTPS egress, applies host-level rules at L7.
  • Agent API
    Container-side shim asks "may I" and submits rule requests for review.

Get started

  1. Build the workspace: cargo build --workspace (Linux required for the daemon).
  2. Run outcalld with NET_ADMIN, SYS_ADMIN, and the Docker socket bind-mounted.
  3. Drop rule YAML into /etc/outcall/rules.d and reload.
  4. Use outcall CLI to inspect bridge, networks, and rules.

Full runtime requirements and CLI flags are in the application README.
